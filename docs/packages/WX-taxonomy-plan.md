**Status: BUILT 2026-09-29 (all seven packages, research only — see section 5).** Originally:
**PLANNED — not implemented.** Review of the operator's "PROMETHEUS —
Weather Market Taxonomy & Extended/Seasonal Modeling" master prompt, written

## 0. Verdict on the prompt

It is right, and it matches how this system is already built: contract
first, settlement source read from the rules, research before trading,
point-in-time data, versioned models, no LLM, production locked. Two facts
found while reviewing it make it more important, not less:

1. Kalshi's "weekly average temperature" markets are **run-length events**,
   not averages: *"at least 6 consecutive days within Sep 28 - Oct 4 on which
   the daily average temperature at KMSY ... "* (KXAVGTKMSY; also KLAS, KPHX -
   18-33k contracts traded). Averaging or multiplying daily probabilities is
   wrong for these twice over (they are dependent, and the event is a run).
2. Hourly markets (KXTEMPxxxH) settle on **AccuWeather at stated
   coordinates**, not The Weather Company - so "one settlement source for
   weather" was never true.

Adjustments to the prompt, for this codebase:
- Add aggregation classes Kalshi actually lists: `RUN_LENGTH` (consecutive
  days meeting a condition), `DAILY_AVG` (station daily average), and
  `CLIMATE_ONE_OFF` (e.g. KXTXURI, multi-year windows) - the prompt's
  WEEKLY_MAX / MONTHLY_MIN remain (KXWEEKHT*, KXMINNYC, KXSJCLOWT).
- "Cloud credits" do not apply: the system runs on one fixed-price droplet.
  The metered resource here is **third-party API quota** (Open-Meteo's free
  tier ~10k calls/day, NWS/BLS rate limits). The budget guard is built for
  that instead, with the same rule: stop, log, never exceed.
- "Dynamic discovery, no fixed 39": today the station list is generated by a
  script (`config/weather_stations.json`); WX-1 makes it a live registry the
  bot refreshes itself, with the JSON kept as the fallback.

## 2. Packages (each: propose -> approve -> build -> server test gate -> deploy)

### WX-1 Contract registry, rules and classifier  (prompt phases 1-4)
- `weather_contracts` table: every Kalshi weather market discovered live
  (series list refreshed daily), normalized fields (variable, unit,
  aggregation, operator, threshold(s), window start/end, station, location).
- `weather_contract_rules`: rules text, sha256, retrieved_at, parser
  version; a changed hash creates a new version and flags dependent models
  for revalidation. Never overwritten.
- Settlement-source record per market parsed from the rule text (TWC,
  AccuWeather + coordinates, NWS CLI, other). Unparseable -> `RESEARCH_ONLY`,
  never tradable.
- `WeatherMarketClassifier`: DAILY_HIGH, DAILY_LOW, DAILY_AVG, HOURLY_TEMP,
  PRECIPITATION, WEEKLY_MAX, WEEKLY_MIN, MONTHLY_MAX, MONTHLY_MIN,
  RUN_LENGTH, SEASONAL, CLIMATE_ONE_OFF, OTHER - rule-text driven, table
  tested against every live series.
- Lifecycle status per market / class: DISCOVERED -> CLASSIFIED ->
  RESEARCH_ONLY -> MODEL_READY -> PAPER_TRADING -> PRODUCTION_ELIGIBLE /
  DISABLED. The live daily high/low path is mapped to PAPER_TRADING (demo
  trading continues exactly as now).
- **No trading change.** The daily estimator reads its series from the
  registry, with `config/weather_stations.json` as the fallback.

### WX-2 Point-in-time weather data layer  (phases 7, 21-26)
- `weather_forecasts`: one row per (source, model, station, valid date,
  variable, issued_at, retrieved_at) - revisions kept, never overwritten.
- History for fitting from Open-Meteo's **previous-runs** API (forecasts as
  issued 1-7 days earlier) - point-in-time by construction.
- Observations with quality flags (VALID / STALE / MISSING / SUSPECT /
  PRELIMINARY / FINAL / REVISED); TWC preliminary AND final stored.
- AccuWeather adapter only if a free, permitted endpoint exists; otherwise
  hourly stays RESEARCH_ONLY (no invented substitute).
- API quota guard (Open-Meteo / NWS / BLS): projected calls vs daily quota;
  stop and log before exceeding.

### WX-3 Source calibration and daily sharpening  (phases 5, 11)
- Calibration table by source x station x horizon x season x variable:
  bias, MAE, RMSE, dispersion; for probabilities Brier, log loss,
  reliability - fitted train / validate / out-of-sample.
- Horizon-dependent error learned from WX-2 (not hard-coded).
- Daily model: replace the fixed representativeness kernel with the
  measured blend error by horizon, so the distribution is as sharp as the
  data supports (today it is wider than the market's). New model version,
  shadow-scored against the current one before it prices anything.

### WX-4 Extended engine: Monte Carlo with temporal dependence  (phases 8-10, 12)
- Daily marginals per day in the window: blend centre + horizon-dependent
  error distribution (WX-3).
- Dependence: error correlation across lead days estimated from WX-2
  history; start with the simplest defensible form (AR(1) on standardized
  errors / Gaussian copula), empirical block bootstrap as the check. A test
  fails if dependence silently collapses to independence.
- Vectorized NumPy simulation, seeded; default 20,000 paths (precision
  ~0.3pt at p=0.5), configurable; run record stores seed, count, input and
  calibration versions.
- Event evaluators on the simulated paths: max >= X, min <= X, average,
  run-length (>= k consecutive days meeting a condition), with the
  contract's own rounding and inclusivity.
- Observed days inside the window are fixed at their observed values (no
  simulation of the past).
- All extended classes start **RESEARCH_ONLY**: probabilities are produced
  and logged, never traded, until WX-6 validation passes.

### WX-5 Hourly model  (phase 6)
- Only after WX-1 confirms the settlement source and WX-2 has a permitted
  data source for it. HRRR + observations at the contract's exact
  coordinates and hour; hourly forecast error by lead.

### WX-6 Matching, paper trading, class-separated validation, dashboard  (phases 13-16, 38-42)
- Net edge per class with model-uncertainty penalty (wider CI -> larger
  required edge); risk engine rejects excessive uncertainty.
- Paper account attributes by class; backtests per class on recorded ticks
  (needs P3b replay), prediction metrics separate from trading metrics.
- Dashboard: class tabs (daily / hourly / weekly / monthly / seasonal /
  research-only / paper), lifecycle status, data quality, settlement source
  per market, and for extended contracts the simulated distribution
  histogram with the threshold probability.

### WX-7 Production eligibility per class  (phase 17)
- Recorded criteria per class: settled sample size, out-of-sample
  calibration, paper performance with CI, execution-cost analysis, risk
  review, explicit operator authorization. Production execution stays
  locked; nothing here unlocks it.

### Settlement sources, as the live rules state them (read 2026-09-29)

Kalshi's help centre (updated 2026-07-22): "Each weather market names its
official settlement source in its market rules ... Always check the specific
market's rules for its source." Daily: NWS Daily Climate Report; hourly: TWC.
The live rules are more varied than that summary, which is why WX-1 reads
every market's own text:

| Class | Series (open today) | Rules name | Detail that matters |
|---|---|---|---|
| Daily high/low | KXHIGH*, KXLOWT* (288 markets) | "(CLIxxx) according to The Weather Company" | TWC publishes the NWS climate-report value (checked 12/12 equal); certification GLOBALTEMPERATURE: Source Agency = NWS |
| Hourly | KXTEMPNYCHS, KXTEMPMIAH, KXTEMPLAXHS, KXTEMPCHIHS (40) | "as reported by Synoptic Data" | Kalshi Weather Index: equal-weight mean of 5-8 ASOS stations (NYCWINDEX etc.), 0.01F |
| Hourly (Apr 2026) | KXTEMPNYCH | "as reported by Accuweather (for coordinates ...)" | not listed now; would not be priced by WX-5 |
| Weekly run-length | KXAVGT* (10 stations, 50 markets) | TWC | day = MEAN OF HOURLY values 00:00-23:59 local, rounded to whole degree; strictly greater; <18 hourly values breaks a streak; data as published at expiration |
| Monthly hourly min | KXSJCLOWT | TWC | ANY single hourly value strictly below T |
| Degree days | KXHDDCVG (Oct-Dec) | TWC | TWC's published HDD(65) per day, summed |
| Precipitation | KXRAIN* | TWC / NWS | no model (RESEARCH_ONLY) |
| Climate one-offs | KXTXURI, KXGTEMP, ... | NWS / NASA / NOAA | no model |

Found in the review: the weekly "average" is NOT (max+min)/2. Phoenix
2026-09-27: TWC hourly mean 87.2F (-> 87), midpoint 88. WX-4 simulates the
hourly mean, calibrated against TWC's own hourly means.
